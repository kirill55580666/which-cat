# Какой ты кот?

Сайт с котом дня, случайными котами и коротким тестом по настроению. Vue 3, TypeScript и Vite; без аккаунтов, backend и внешних AI-запросов.

## Запуск

Node.js 22.12+ и npm:

```sh
npm ci
npm run dev
```

```sh
npm test
npm run build
npm run preview
```

## Как это работает

- 60 персонажей, 240 описаний, 60 поручений, 20 вопросов; в тесте случайно выбираются пять.
- Кот дня сохраняется до смены локальной календарной даты. Первая встреча — Чунявый Бенедикт. Дневная и случайная очереди независимы; каждый образ показывается один раз за цикл очереди.
- Случайная выдача по возможности избегает последних десяти показанных образов. Четыре описания каждого кота выдаются без повторов до исчерпания своего набора.
- Ответы теста суммируют баллы по пяти настроениям; побеждает максимальная сумма. При ничьей приоритет: уют, величие, нежность, хаос, исследование. Недавно показанные коты подходящего настроения исключаются, пока есть альтернативы.
- История и кот дня остаются в localStorage этого браузера. Очистка данных начинает историю заново. При запрете хранения приложение работает в памяти текущей вкладки.
- «Скачать» рисует PNG-открытку из текущего кота, текста, двух характеристик и поручения. Их проценты шуточные, независимые и не обязаны давать в сумме 100. Избранного нет.

## Контент и рисунки

`src/data/cats.ts` — персонажи и четыре отдельных описания каждого. `src/data/questions.ts` — вопросы и веса ответов. `src/assets/cats-{1,2,3}.png` — три атласа по двадцать самостоятельных рисунков, сетка 5 × 4. Арт указывается индексом 0–59. Точные области рисунков по белым промежуткам задаются в `src/artRects.ts`; интерфейс и PNG-экспорт используют одни и те же границы. Рисунки созданы встроенным ImageGen; записанное пользователем видео использовалось только как визуальный референс и не публикуется. Макет в `docs/design/` — предварительная проба, его старые кнопки избранного не входят в приложение.

Шрифты Caveat и Nunito поставляются локально по SIL Open Font License; лицензии рядом с файлами в `src/assets/`.

## Публикация

Публичный репозиторий: https://github.com/kirill55580666/which-cat

В Settings → Pages выбрать Source → GitHub Actions. Workflow `.github/workflows/pages.yml` проверяет тесты и типы, собирает приложение и после успешных проверок публикует push в `main`. Для pull request выполняются только проверки. Доступен ручной запуск workflow. `base: './'` позволяет работать в подпапке Pages без серверной маршрутизации.

Секреты приложению не нужны. Для отката — `git revert` нужного коммита и push в `main`; CD опубликует исправленное состояние.
